# やみのりゅう — ドット絵JRPG

ドラクエ／FF型の見下ろしRPG。**ブラウザだけで動き、外部ファイルを1つも使わない**（画像0枚・音声0個・ライブラリ0個）。

### ▶ [ブラウザで遊ぶ](https://kubo-sketch.github.io/yaminoryu/)

ドット絵はすべてコードで生成し、BGM5曲と効果音19種は WebAudio で合成しています。
リポジトリにあるのは HTML と JavaScript だけです。

---

## 遊ぶ

```bash
cd prototype-rpg
python3 -m http.server 8765
# → http://localhost:8765/ を開く
```

`index.html` を直接ダブルクリックしても動きますが、`file://` では localStorage が不安定なので**セーブを試すならサーバー経由**にしてください。

| 操作 | キー | スマホ |
|---|---|---|
| 移動 | 矢印／WASD | 画面下の十字 |
| 話す・調べる・決定 | Z／Space／Enter | けってい |
| メニュー・キャンセル | X／Esc | メニュー |
| 音のON/OFF | 画面右上 🔊 | 同じ |
| セーブ削除 | 画面右上 🗑 | 同じ |

### セーブについて（サーバー・DBは使いません）
- **各自のブラウザに保存されます**（localStorage）。他人のデータと混ざりません
- 起動時に `navigator.storage.persist()` を要求します。Safari は7日間サイトを
  訪れないと保存領域を消すため、その対象から外れる可能性を上げるためです
- **端末をまたぎたいときはタイトルの「データ」から**。文字列をコピーして
  別の端末で貼り付ければ続きから遊べます。サーバーを持たずに引き継ぐ仕組みです
- シークレットモードでは保存されません（ブラウザの仕様）

## 遊べる範囲

「歩ける・話せる・買える・泊まれる・戦える・成長する・セーブできる・クリアできる」が
1周ぶん通っています。本編クリアのあとに寄り道と隠しボスがあります。

1. **はじまりの村** — どうぐや／ぶきや／やどや／村長（セーブ）＋村人11人、石畳の広場と噴水、墓地
2. **村長に話す** → 洞窟の封印が解ける（進行フラグ）
3. **フィールド** — 街道・川と橋・森・宝箱2つ。川より北は敵が強い
4. **みなとまち シオカゼ**（東）— 上位の武具を扱う。船長がボスの弱点を教えてくれる
5. **ふるい とうだい 1F〜最上階**（寄り道・推奨Lv6〜7）— 学者ガレンの研究記録があり、
   竜に輪を嵌めた犯人と、若者3人が実験台にされていた事実が判る。最上位装備2種
6. **やみのほらあな 1F〜2F** — 視界が松明ぶんだけに狭まる。宝箱に てつのやり／くさりかたびら
7. **ボス「やみのりゅう」** — HPゲージ表示・ほのおのいき・ベギラマ
8. **エンディング** — 到達状況で内容が変わる（竜の真相を知ったか、依頼を果たしたか、黒幕を討ったか）

### 裏ボス
竜を倒すと**灯台の奥の間が開く**。そこに黒幕の学者ガレンが待っている（推奨Lv10）。
撃破すると称号が「わを くだきし者」になり、エンディングに顛末が加わる。

### サブクエスト・読み物
- **「かえらぬ3人」** — 墓地の墓守が、半年前に洞窟へ向かい戻らなかった若者3人の
  手がかりを探してほしいと頼む。洞窟1階でペンダントを見つけて報告すると報酬
- **日記3枚**（洞窟1階に2枚・2階に1枚）— 竜がなぜ闇に落ちたのかが断片的に判る。
  3枚すべて読むとエンディングが変わり、竜の名誉が回復する

プレイ時間は**本編で約60分、やり込みを含めて2〜3時間**。
マップ12枚・歩行可2850マス・敵16種・呪文16種・レベル上限40。

### 進行の流れ
```
はじまりの村 ─→ フィールド ─→ やみのほらあな（中ボス）─→ やみのりゅう ─→ エンディング
     │              ├─→ みなとまち シオカゼ（上位装備・弱点の情報）
     │              ├─→ ふるい とうだい（黒幕の記録・最上位装備）
     │              └─→ やまごえの みち（伝承）
     │
     └─ 竜を倒したあと ─→ 灯台の奥（黒幕ガレン）
                       ─→ 海底アルシオン（輪の起源）
                       ─→ りゅうのはか（初代の竜・卵）
                       ─→ ふかいの ま（隠しボス）
```世界設定は [WORLD_BIBLE.md](WORLD_BIBLE.md) に集約。

## 実装されているもの

- 4方向歩行アニメ・グリッド移動・当たり判定・カメラ追従・落ち影
- 木や屋根の上部をキャラより後に描く上レイヤー（木の陰に入れる）
- 環境レイヤー：屋外はカメラの0.55倍で流れる雲の影（視差）、洞窟は光の粉塵
- 家具・装飾タイル23種（ベッド／テーブル／本棚／噴水／ベンチ／荷車／花壇／
  石畳／墓標／木箱／鍾乳石／水たまり／獣骨 ほか）
- ランダムエンカウント（場所別テーブル／戦闘直後は3歩の猶予）
- ターン制戦闘（たたかう・じゅもん・ぼうぎょ・どうぐ・にげる）
  - ダメージ式 `(こうげき力 − しゅび力/2) × 0.85〜1.15`、会心の一撃 1/32
  - **敵は最大3体まで同時出現**し、単体攻撃は対象を選ぶ
  - **属性**（ほのお／こおり／いかずち）と敵ごとの弱点1.6倍・耐性0.5倍
  - **ぼうぎょ**（被ダメージ半減＋MP微回復）
  - 呪文8種（ホイミ／ベホイミ／メラ／ヒャド／ベギラマ／ライデイン／ラリホー／ルカニ）
  - **中ボス**が2階への階段を塞ぐ関門になっている
  - **ボスはHPが半分を切ると形態変化**し、攻撃力とブレス率が上がる
  - ダメージ数字のポップアップ、敵の待機モーション、被弾の白フラッシュ
  - 戦闘中のメッセージは自動送り（ボタンで即スキップ）。1手ごとに押させると
    雑魚戦が冗長になり手触りが最も悪くなるため
  - **攻撃モーション**：斬撃の光跡（会心は2本）、炎の火の粉、降る氷結晶、
    落雷、敵の爪痕、闇の渦。当たった瞬間に時間を止めるヒットストップ付き
- **パーティ制**（主人公＋最大2人）。全員のコマンドを入力してから一斉実行、
  戦闘不能と蘇生、仲間は主人公のレベルに追随
- レベル1〜**40**の成長（式で生成）、呪文15種、武器5種・防具5種
- 店（購入・所持金・すでに上位装備なら断る）、宿屋、宝箱、看板
- 死亡時は村で復活・ゴールド半減
- セーブ／ロード（localStorage・村長に話すと記録）
- BGM 6曲を4声（主旋律／副旋律／アルペジオ／ベース）＋ドラム＋ディレイで合成。
  デューティ比25%/12.5%のパルス波とビブラートでSFC音源に寄せている
- 効果音19種
- イベント演出（カメラを振る・キャラを自動で歩かせる・間を置く）。
  オープニング、村長の依頼、ボスの目覚めで使用
- スマホの仮想パッド／iOSの音アンロック
- **名前入力**（かな表から6文字まで。濁点・半濁点、かな／カナ切替）

## ファイル構成

```
index.html          レイアウトとCSS（キャンバス720x624・仮想パッド）
src/sprites.js      全グラフィックをコードで生成（タイル41種・キャラ11種・敵6種96x96）
src/data.js         ★バランス定数の全部。手触り調整はここだけ触る
src/maps.js         マップ4枚。文字列直書きではなくGridで組む（幅ズレ防止）
src/engine.js       描画基盤・入力・ウィンドウ・メッセージ・画面効果
src/audio.js        BGMと効果音の合成
src/field.js        歩行・イベント・エンカウント・宿屋
src/cutscene.js     イベント演出（カメラ移動・自動歩行・場面スクリプト）
src/battle.js       戦闘
src/ui.js           メニュー・店・確認ダイアログ
src/main.js         起動・状態遷移・セーブ・タイトル・エンディング
tests/              node で回る検証スクリプト（下記）
```

**依存は一方向**：`data`/`maps`/`sprites` ← `engine`/`audio` ← `field`/`battle`/`ui` ← `main`。
数値はロジックに埋めず `data.js` に集約してあるので、**バランス調整で他のファイルを触る必要はありません**。

### なぜドット絵をコードで生成しているのか

素材サイト（ぴぽや倉庫等）からダウンロードする方式は、**あなたが手を動かすまで1マスも動きません**。
コード生成にすれば起動した瞬間に動き、色替えでNPCを量産でき、配布もフォルダを渡すだけで済みます。
`sprites.js` の `makeChar({hair, body, ...})` に色を渡すだけで新しいNPCが1行で増えます。

見た目を上げたくなったら、後から素材に差し替えられます（`G.TILE` / `G.SPR` に `<img>` を入れるだけ）。

## 検証（node だけで回る／ブラウザ不要）

```bash
node tests/verify_maps.js    # マップ整合性 + 到達可能性(BFS)
node tests/smoke.js          # 全画面の update+draw を実行して実行時エラー検出
node tests/balance.js        # 戦闘を数千回自動プレイして勝率を出す
node tests/story.js          # クエストの順序・報酬の二重取り・エンド分岐・仲間・状態異常
```

`verify_maps.js` は**スタート地点から歩いてボスまで到達できるか**をBFSで確認します。
作成中、実際に次の2つの詰みを検出しました。

- フィールドの村の入口が屋根で塞がれ、**町から出た瞬間に一歩も動けない**状態だった
- 洞窟1Fの宝箱への通路が本線と繋がっておらず、**到達不能な宝箱**があった

`verify_maps.js` は加えて **NPCによる通路の封鎖・1マス幅の隘路・孤立領域**も検出します。
キャラを縦長にしたあとに調べたところ、当たり判定は足元1マスなので通行性自体は変わって
いませんでしたが、別の問題が見つかりました。

- 3×3の部屋の中央に店主を置いていたため、**店主の背後の区画に一生入れない**（店4軒すべて）
- 村長の家は隅に置いた松明2つで**部屋が上下に分断**されていた
- ぶきやは扉の正面がカウンターで**部屋に入れなかった**
- 川を蛇行させた際、街道を引き直す順序のせいで**橋が架からず川の上を歩けた**

いずれも「部屋を内寸6×5まで広げ、店主は扉から遠い壁際、小物は隅」という規則に直しました。

`smoke.js` は canvas をスタブして全シーンを実際に走らせます。これで検出したもの：

- フィールドが確認ダイアログを処理しておらず、**宿屋の「はい」に応答できなかった**
- `fadeIn` が既に明転済みのときコールバックを呼ばず、**操作不能で固まる経路**があった

### 現在のバランス実測（`node tests/balance.js`）

**人数別のボス勝率**（仲間は任意加入なので、1人でもクリアできることを保証している）

| ボス | 推奨Lv | 1人 | 2人 | 3人 |
|---|---|---|---|---|
| やみのりゅう | 7〜8 | 44% | 41% | 91% |
| ガレン（裏） | 10 | 99% | 94% | 100% |
| はじまりの りゅう | 20 | 97% | 78% | 91% |
| ヴェルドの まぼろし（隠し） | 32〜36 | 0% | 25% | 39% |

敵の行動回数を「こちらの生存人数まで」に制限しているため、人数を増やしても
相対的な脅威が保たれます。これが無いと、1人で即死・3人で作業、に二極化します。

**レベリング**：Lv10到達まで平均61戦・死亡0.5回・所要約40分。

## 手触り調整の入り口

数値は全部 `src/data.js` にあります。実機で触って違和感があったら次を動かしてください。

| 気になった点 | 触る場所 |
|---|---|
| 戦闘が多すぎる／少なすぎる | `G.ENC.*.rate`（0.055〜0.10） |
| レベルが上がるのが遅い | `G.LEVELS[].exp` |
| 敵が強い／弱い | `G.ENEMIES[].atk` `.def` `.hp` |
| ボスが理不尽 | `G.ENEMIES.boss.breath`（ブレス率）と `.spell.rate`、`.rage`（形態変化） |
| 敵が出すぎる／少ない | `G.ENEMIES[].max`（同時出現数の上限） |
| 属性の効きすぎ | `G.elemMul`（弱点1.6倍・耐性0.5倍） |
| 装備が買えない | 敵の `.gold`、または `G.WEAPONS[].price` |
| 歩くのが遅い | `src/field.js` の `MOVE_MS`（145ms） |
| 文字送りが遅い | `src/engine.js` の `MSG_SPEED`（26ms/字） |

**AIで代替できないのは「触った感じが良いかどうか」の判断だけです。** 上の表以外を触る必要が出たら、
それは仕様の穴なので先に決めてから実装してください。

## ここから伸ばすなら

いま骨格は全部揃っているので、**追加はデータを足す作業**になります（コードを増やす作業ではない）。

- **町を増やす** — `maps.js` に `buildTown2()` を足して `warp` で繋ぐ。所要1〜2時間／1つ
- **敵を増やす** — `data.js` の `G.ENEMIES` に1行＋`sprites.js` に描画関数1つ
- **仲間を入れる** — ここは骨格の変更。`battle.js` を単体→パーティ制に直す必要があり、
  FF型のサイドビューにするなら味方のバトルスプライトも必要になる（素材コストが跳ねる）
- **見た目を上げる** — 色数を増やさず、タイルのバリエーションを増やすほうが効きます
  （「安っぽさ」の原因は解像度ではなく視覚的一貫性の欠如）

## 絵を確認する（ブラウザ不要）

```bash
node tools/render_preview.js        # preview/ に PNG を書き出す
```

Canvas2D のうち必要な分だけを node 上に実装し、スプライトと実際のゲーム画面を
PNG に落とします（外部パッケージなし）。ドット絵は**見ないと調整できない**ので、
`sprites.js` を触ったら必ずこれで確認してください。

出力されるもの：タイル一覧／キャラ一覧（全方向・全コマ）／敵一覧／
町・フィールド・洞窟の実画面／戦闘画面。
